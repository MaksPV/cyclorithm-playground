# Плейграунд Cyclorithm

[Открыть плейграунд](https://MaksPV.github.io/cyclorithm-playground/)

Плейграунд рассчитывает расписания Cyclorithm прямо в браузере. Редактор
показывает исходный текст, шкала времени — интервалы циклов и моменты
событий, а таблица — время, действие, точку и атрибуты каждого события.
[Справочник языка](https://MaksPV.github.io/cyclorithm/).

## Работа с расписанием

1. Откройте свой файл `.cyclo` или измените пример в редакторе. Файл можно
   создать кнопкой **+ Новый**, выбрать кнопкой **Загрузить** или перетащить
   в панель файлов.
2. Задайте начало и конец окна в полях **start** и **end**. В таблицу
   попадут события с начала окна до его конца. Событие ровно в **start**
   входит в окно, а событие ровно в **end** остаётся за его пределами.
3. Нажмите **Развернуть**. Колесо мыши или кнопки **+** и **−** меняют
   масштаб шкалы. Перетаскивание сдвигает видимый интервал. Кнопка **⤾**
   возвращает исходный масштаб.

Если в окне больше 2000 событий, плейграунд предложит сузить интервал.
Редактор подсвечивает синтаксис Cyclorithm. При синтаксической ошибке он
выделяет строку, если движок указал её номер. Остальные ошибки отображаются
текстом рядом с параметрами запуска.

### Часовые пояса

- **Запрос** задаёт смещение начала и конца окна. В режиме **Наивно**
  границы отправляются без суффикса. Для UTC отправляется `Z`, для
  фиксированного смещения — `±HH:MM`. Если у даты в программе нет
  смещения, движок использует `timezone` расписания или, при её
  отсутствии, смещение начала окна.
- **Шкала** задаёт смещение для подписей и размещения отметок. Событие
  с суффиксом размещается по его абсолютному времени. Событие без суффикса
  размещается по указанному местному времени в зоне шкалы. Таблица
  и подсказки показывают время в том виде, в котором его вернул движок.

Движок поддерживает фиксированные смещения от UTC. Правила интерпретации
дат и вывода описаны в [документации Cyclorithm](https://MaksPV.github.io/cyclorithm/dev/reference/semantics/#time-zones).

## Файлы и библиотеки

Пользовательские файлы сохраняются в локальном хранилище браузера.
Чтобы подключить один файл из другого, укажите путь в `use` так, как он
отображается в панели. Пользовательский файл можно переименовать двойным
щелчком по его имени. Если файл подключён через `use`, обновите путь в
расписании.

Раздел **Библиотеки** показывает файлы из [манифеста](libs/manifest.json).
Плейграунд загружает их с сайта при открытии страницы. Кнопка **обновить**
загружает библиотеки повторно и пересчитывает расписание. Библиотеку можно
открыть для просмотра. Чтобы редактировать своё расписание, снова
выберите пользовательский файл.

Если путь пользовательского файла совпадает с путём библиотеки с сайта,
при импорте используется библиотека с сайта. Для своей версии выберите
другое имя файла. Чтобы добавить библиотеку на сайт, поместите файл в
[libs/](libs/) и добавьте путь в массив `libs` манифеста. Импортируемый
файл может содержать объявления и свои директивы `use`. Точки, циклы и
рутины объявляются в файле с блоком `schedule`.

## Синтезатор

Включите панель кнопкой **Синт**. По умолчанию синтезатор выключен, а
браузер загружает [плагин](plugins/synth.js) при первом включении. Кнопка
**Play** начинает воспроизведение с начала окна запроса, **Stop** его
останавливает. Синтезатор получает новые события порциями и продолжает
воспроизведение после конца видимого окна. Масштаб шкалы не влияет на
скорость звука. Если в очередной порции
нет событий, ничего не звучит и с последнего события прошло больше
15 секунд, воспроизведение останавливается.

Для каждой ноты нужно событие `note_on` и соответствующее событие
`note_off`. Точка определяет голос. У `note_off` с явно заданной высотой
выбирается последняя открытая нота той же точки с совпадающим значением
в том же формате. Вызов `note_off()` без высоты закрывает последнюю
открытую ноту на этой точке.

Высоту можно задать одним из трёх способов. Синтезатор ищет подходящее
значение в порядке `freq` (герцы), `midi` (69 соответствует ля первой
октавы) и `note` (например, `"A4"`). Каждое из этих полей берётся из
атрибутов действия, а при его отсутствии — из атрибутов точки.

| Атрибут точки | Назначение |
| --- | --- |
| `wave` | Форма волны: `sine`, `triangle`, `square`, `sawtooth` или `noise`. По умолчанию `sine`. |
| `attack`, `release` | Время нарастания и затухания в миллисекундах. По умолчанию 10 и 100 мс. |
| `volume` | Громкость голоса от 0 до 1. По умолчанию 1. Громкость на панели применяется ко всем голосам. |
| `filter`, `cutoff` | Для белого шума можно выбрать `lowpass` или `highpass` и указать частоту среза в герцах. |

Для `wave = "noise"` высота нужна для сопоставления событий. Например,
для хай-хэта можно указать `wave = "noise"`, `filter = "highpass"`,
`cutoff = 7000` в атрибутах точки и передать `HAT_F` в поле `freq` у
события `note_on`.

### Пример с музыкальной библиотекой

Библиотека содержит константы частот нот от `C2` до `B5`, включая бемоли
вроде `Bb4` и `Eb5`, и частоты для ударных вроде `KICK_F` и `HAT_F`.
Функции интервалов строят новые частоты от заданной. Например, `MIN3`
повышает её на малую терцию, а `FIFTH` — на квинту. Гаммы `AM_MIN`,
`AM_PENT` и `C_MAJ` доступны как массивы.
Все таблицы ритма рассчитаны на 120 ударов в минуту. [music_lib.cyclo](libs/music_lib.cyclo)

| Таблица | Слоты |
| --- | --- |
| `GRID4`, `GRID8`, `GRID16` | Четверти `q1–q4`, восьмые `g1–g8`, шестнадцатые `x1–x16`. Такт длится 2 секунды. |
| `WALTZ3` | Три четверти `w1–w3`. Такт длится 1,5 секунды. |
| `PHRASE_2`, `PHRASE_4`, `PHRASE_8`, `PHRASE_16` | Фразы на 2, 4, 8 и 16 тактов со слотами `t1`, `t2` и далее. |

Вставьте пример ниже в редактор. Установите **start** на 1 января 2026
года, 00:00, **end** на 00:01 и выберите режим **Наивно** в поле
**Запрос**. Нажмите **Развернуть**. В таблице появятся события
`note_on` и `note_off`. Затем включите **Синт** и нажмите **Play**.

```cyclo
use "libs/music_lib.cyclo";

schedule "Моя песня" {
  point LEAD {
    actions = [note_on, note_off];
    attrs = {"wave": "sawtooth", "attack": 5, "release": 200, "volume": 0.8};
  }

  routine RIFF(TC) {
    x1: LEAD.note_on() {"freq": AM_PENT[4]};
    x2: LEAD.note_off();
    x3: LEAD.note_on() {"freq": FIFTH(A2)};
    x4: LEAD.note_off();
  }

  root_cycle start_time = "2026-01-01T00:00:00", duration = 8s {
    0s: repeat 4 RIFF(GRID16);
  }
}
```

## Локальный запуск

Понадобятся Rust с `rustup` и Python 3. Из корня репозитория выполните:

```sh
./run.sh
```

Скрипт проверяет наличие цели `wasm32-unknown-unknown` и нужной версии
`wasm-bindgen-cli`, собирает WebAssembly и запускает HTTP-сервер.
Откройте [локальный плейграунд](http://localhost:8080/). Через
`./run.sh 8090` можно выбрать другой порт. Для остановки нажмите **Ctrl+C**.

Чтобы выполнить те же шаги вручную, установите инструменты и соберите пакет:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.100 --locked
cargo build --locked --release --target wasm32-unknown-unknown
wasm-bindgen target/wasm32-unknown-unknown/release/playground.wasm --out-dir pkg --target web
python3 -m http.server 8080
```

Версия программы `wasm-bindgen` должна совпадать с версией зависимости
в [Cargo.toml](Cargo.toml).

## Интерфейс WebAssembly

Версия ядра [Cyclorithm](https://github.com/MaksPV/cyclorithm) закреплена
коммитом в [Cargo.toml](Cargo.toml) и [Cargo.lock](Cargo.lock). Публичные
функции обёртки находятся в [src/lib.rs](src/lib.rs):

| Функция | Результат |
| --- | --- |
| `expand_it(src, start, end, libs_json)` | События окна `[start, end)`. |
| `expand_timeline(src, start, end, libs_json)` | События окна с интервалом цикла в `event.span` и списком уникальных интервалов в `spans`. |
| `next_steps(src, from, within_ms, n, libs_json)` | До `n` ближайших событий в окне длительностью `within_ms` от `from`. Поле `next` содержит время для следующего запроса. |

`libs_json` — JSON-массив пар `[путь, текст]`. Функции возвращают
JSON-строку. Успешный ответ `expand_it` для окна без событий выглядит так:

```json
{
  "ok": true,
  "result": {
    "schedule": "Пример",
    "start": "2026-01-01T00:00:00",
    "end": "2026-01-01T00:01:00",
    "events": []
  }
}
```

При ошибке в ответе будет объект диагностики:

```json
{
  "ok": false,
  "diag": {
    "kind": "valid",
    "code": "unknown-cycle",
    "line": null,
    "col": null,
    "text": "unknown-cycle: unknown cycle 'X'"
  }
}
```

В запросе `next_steps` курсор сдвигается на одну миллисекунду после
последнего возвращённого события. Если событий нет, курсор указывает на
конец окна. При разбиении на порции события с одинаковым временем могут
попасть на границу: события с тем же временем, оставшиеся после
достижения лимита `n`, следующий запрос по этому курсору пропустит.

## Проверки и публикация

Для запуска WASM-тестов установите Node.js и
`wasm-bindgen-test-runner` из того же комплекта, что и `wasm-bindgen`.

```sh
cargo check --locked
cargo check --locked --target wasm32-unknown-unknown
CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER=wasm-bindgen-test-runner \
  cargo test --locked --target wasm32-unknown-unknown
```

Проверенные изменения попадают в `dev`. Сайт на GitHub Pages собирается
при отправке изменений в `main`. Правила работы с ветками приведены
в [AGENTS.md](AGENTS.md), конфигурация сборки — в
[pages.yml](.github/workflows/pages.yml).
