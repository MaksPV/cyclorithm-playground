# cyclorithm-playground

Живой сайт: https://MaksPV.github.io/cyclorithm-playground/

WASM-плейграунд для Cyclorithm (v1 — визуализатор): редактор кода слева,
таймлайн (дорожки циклов-прямоугольников + точки событий) и таблица справа,
окно выбирается мышью, ошибки — панелью с выделением строки.

Движок — `cyclorithm-core` из основного репозитория
(`https://github.com/MaksPV/cyclorithm`, ветка `dev` — интеграция, `main` — релиз, фасад `core::api`).
Контракт: `expand_it(src, start, end, libs_json)` →
`{"ok":true,"result":{...}}` / `{"ok":false,"diag":{...}}`;
`expand_timeline` — то же плюс спаны (`event.span`, distinct-список `spans`);
`next_steps(src, from, within_ms, n, libs_json)` — первые `n` событий из
`[from, from+within)`, плюс `result.next` (ISO-курсор за последним событием,
в зоне движка) — поток для бесконечного расписания.

## Зоны: запрос и шкала

- Селект «запрос» — зона окна, уходящего в движок: `Наивно` (строки без
  суффикса — движок читает их в кадре `timezone` файла), `UTC` (явный `Z`),
  `UTC±HH:MM` (явный пояс). Наивный файл + наивный запрос — ответ наивный
  1:1; иначе ответ несёт зону (суффикс), таблица и тултипы показывают
  строки движка как есть.
- Селект «шкала» — только подписи и ось: наивные строки рисуются стеной
  в зоне шкалы, строки с суффиксом — своим инстантом.
- Движок знает только фикс-офсеты (`Z`/±HH:MM), без DST и IANA.

## Сборка

Быстрый запуск (проверка тулов, сборка WASM, клей, сервер на 8080):

```console
$ ./run.sh [PORT]
# открыть http://localhost:8080
```

Вручную (тот же конвейер по шагам).
Требуется `wasm-bindgen-cli` той же версии, что `wasm-bindgen` в `Cargo.toml`
(сейчас `0.2.100`):

```console
$ cargo build --release --target wasm32-unknown-unknown
$ wasm-bindgen target/wasm32-unknown-unknown/release/playground.wasm \
    --out-dir pkg --target web
$ python3 -m http.server 8080
# открыть http://localhost:8080
```

Тесты — в настоящем WASM под node (раннер `wasm-bindgen-test-runner`
из того же комплекта; переменная окружения — разово):

```console
$ export CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER="wasm-bindgen-test-runner"
$ cargo test --target wasm32-unknown-unknown
```

## Синтезатор (плагин `plugins/synth.js`, по умолчанию выключен)

Плагин включается кнопкой «Синт» в ряду тоглов (состояние хранится в
раскладке) и подгружается лениво через dynamic import — пока выключен, его
кода нет даже в памяти. Панель: Play/Stop, общая громкость (мастер) и
статус. Хук статуса — `synth.update(inView, {t0,t1})` в конце `draw()`
(звук от вида не зависит).

События `note_on`/`note_off` звучат осциллятором WebAudio
(`point` — голос, полифония по разным `point`).
Высота — из `action_attrs` с fallback на `point_attrs`:
`freq` (Гц) → `midi` (69 = A4) → `note` (`"A4"`).
Тембр голоса — из `point_attrs`, читается в момент `note_on`:
`wave` (`sine`/`triangle`/`square`/`sawtooth`/`noise`, иначе `sine`),
`attack`/`release` (миллисекунды, по умолчанию 10/100),
`volume` (0..1, по умолчанию 1, умножается на мастер).
Шум (`wave = "noise"`, зацикленный буфер белого шума): высота игнорируется,
но pitch обязан быть — он нужен паре `on`/`off`; опционально `filter`
(`lowpass`/`highpass`) + `cutoff` (Гц) — фильтр действует только на шум:

```
point LEAD {
  actions = [note_on, note_off];
  attrs = {"wave": "sawtooth", "attack": 5, "release": 200, "volume": 0.8};
}
point HAT {
  actions = [note_on, note_off];
  attrs = {"wave": "noise", "filter": "highpass", "cutoff": 7000, "release": 20, "volume": 0.3};
}
cycle MELODY duration = 8s {
  0s: LEAD.note_on() {"freq": 440};
  1s: LEAD.note_off();
}
```

Расписание бесконечно (`root_cycle` повторяется вечно), поэтому звук —
**поток строго в realtime** (1 мс шкалы = 1 мс аудио, выбора скорости нет):
Play берёт события пачками через `next_steps` (стартовый курсор —
начало окна запроса, та же строка, что у таймлайна), планирует ноты в
WebAudio с запасом ~2 с и продолжает, пока не нажали Stop. Парность
`note_on/note_off` сквозная через пачки: `on` открывает голос (атака в
момент события), `off` закрывает (release); висячий `on` тянется до
ближайшего `off`. Пейринг — стеком на `point|pitch`; `note_off()` без блока
закрывает верхний открытый голос. Если событий и звука нет дольше 15 с,
поток останавливается сам.

## Библиотеки (`use`, папка `libs/`)

Библиотеки — обычные файлы в папке `libs/` репозитория, в код не вшиты.
`libs/manifest.json` перечисляет пути (`["libs/route_lib.cyclo", ...]`);
плейграунд подтягивает их fetch'ем при старте (кнопка «обновить» в панели
файлов перечитывает с хоста и пересчитывает). Источник правды — хост:
в localStorage не хранятся, в редакторе не правятся (в панели — отдельный
список «Библиотеки», только чтение). Новая либа = файл + строка в манифесте.
Свои файлы с теми же путями движку не отдаются (побеждает хост).
Клик по библиотеке открывает её в редакторе строго для просмотра
(печатать нельзя); клик по своему файлу возвращает редактирование.
Текст либы никуда не сохраняется — `run()` при открытой либе честно
покажет ошибку движка.

## Музыкальная библиотека (`libs/music_lib.cyclo`)

Подключается строкой `use "libs/music_lib.cyclo";`. Даёт:

- ноты `C2–B5` констами (частоты в Гц, бемольные имена: `Bb4`, `Eb5`);
- высоты ударных: `KICK_F`, `SNARE_F`, `HAT_F`, `HAT2_F`, `CLAP_F`,
  `TOM_LO_F`, `TOM_HI_F`, `RIM_F`, `CRASH_F`, `RIDE_F`;
- интервалы `fun` вверх от любой частоты: `OCT`, `OCTD`, `SEMI`, `TONE`,
  `MIN3`, `MAJ3`, `FOURTH`, `FIFTH`, `MIN6`, `MAJ6`, `MIN7`, `MAJ7`
  (Am тремя голосами: `A2` + `MIN3(A2)` + `FIFTH(A2)`);
- гаммы массивами (доступ `AM_PENT[4]`): `AM_MIN`, `AM_PENT`, `C_MAJ`;
- сетки времени, все на 120 BPM: `GRID4` (четверти `q1–q4`),
  `GRID8` (восьмые `g1–g8`), `GRID16` (шестнадцатые `x1–x16`, такт 2000 мс),
  `WALTZ3` (3/4, такт 1500 мс, `w1–w3`), фразы `PHRASE_2`/`4`/`8`/`16`.

Пример песни:

```
use "libs/music_lib.cyclo";

schedule "Моя песня" {
  point LEAD {
    actions = [note_on, note_off];
    attrs = {"wave": "sawtooth", "attack": 5, "release": 200, "volume": 0.8};
  }
  routine RIFF(TC) {
    x1: LEAD.note_on() {"freq": AM_PENT[4]};
    x2: LEAD.note_off();
    x3: LEAD.note_on() {"freq": FIFTH(A2)};
    x4: LEAD.note_off();
  }
  root_cycle start_time = "2026-01-01T00:00:00", duration = 8s {
    0s: repeat 4 RIFF(GRID16);
  }
}
```

Честные ограничения (диктует движок, не мы): в либу нельзя положить
`point`, `routine` и `cycle` — импорт с расписанием бракуется ошибкой
`schedule-in-import`, поэтому тембры и рутины живут в файле песни.
Свои `const` нот при подключении либы надо удалить (коллизия имён);
слоты рутин — под имена `q*`/`g*`/`x*`/`w*`/`t*`, либо держать свой `BAR`
локально. Либу не править в панели — она перезаписывается с хоста;
кастомизация — своими файлами.

## Ограничения v1 (честно)

- Окно с более чем 2000 событиями не разворачивается: перед `expand_timeline`
  идёт дешёвый замер `next_steps` (первые 2001 событие); при перегрузе
  показывается «увеличьте масштаб (сузьте окно)», а данные не материализуются.
- Свои файлы для `use` — через «Новый»/«Загрузить» или драг-н-дроп в панель (путь — как в исходнике); встроенные либы — из папки `libs/` (см. выше).
- Подсветка в редакторе — только выделение строки синтаксической ошибки;
  E-ошибки — текстом (у них нет позиций, см. `features/gui_editor.md`).
- Деплой на GitHub Pages — workflow `.github/workflows/pages.yml`
  (сборка WASM в CI при пуше в `main`).
